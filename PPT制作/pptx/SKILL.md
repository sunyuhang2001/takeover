# 学术论文汇报 PPT 生成规范

当用户上传论文 PDF 或 md 文件时，按本规范提取内容、规划结构、生成完整学术汇报 PPT。生成目标不是论文摘要，而是一套适合**论文汇报 / 文献汇报 / 组会报告 / 开题汇报**的演示文稿。

---

## §1 输入处理与忠实性原则

### 输入类型

- 论文 PDF → `python -m markitdown paper.pdf` 提取文本
- 论文 md 文件 → 直接读取
- 其他可解析论文文本

### 忠实性原则

所有内容必须源自上传文件。

| 允许 | 禁止 |
|------|------|
| 基于上下文做谨慎推断 | 虚构数据、实验结果、统计数值 |
| 对冗长段落做学术性精简 | 虚构期刊名称、影响因子、JCR 分区 |
| 基于局限性归纳展望方向 | 脱离论文内容的过度发挥 |

**缺失时**：省略该项，或标注"文中未明确说明"/"待补充"。

---

## §2 演讲框架

严格按以下结构生成，共 15-18 张幻灯片。

| 序号 | 章节 | 页数 | 来源章节 |
|------|------|------|----------|
| 1 | 封面 | 1 | 元数据 |
| 2 | 目录 | 1 | 自动生成 |
| 3 | 研究背景与意义 | 1-2 | Introduction |
| 4 | 研究目的与假设 | 1 | Introduction |
| 5 | 研究方法 | 2-3 | Methods |
| 6 | 主要结果 | 3-4 | Results / Figures / Tables |
| 7 | 讨论与解读 | 2-3 | Discussion |
| 8 | 结论与局限性 | 1-2 | Conclusion / Limitation |
| 9 | 未来展望 | 1 | Discussion / Future Work |
| 10 | 致谢与参考文献 | 1 | Acknowledgements / References |

---

### 各章节要点

- **封面**：原文标题（不得改写）、汇报人、日期、期刊名。影响因子/JCR 分区无法确认则标"待补充"，不得虚构
- **目录**：列出主要章节名称，与后续标题一致
- **研究背景**：来自 Introduction。第 1 页写领域现状，第 2 页写研究空白与意义。**不得泄露结果**
- **研究目的**：提取 aim/objective/hypothesis。无明确假设则只写目的，**不得生造假设**
- **研究方法**：按原文拆分（设计、样本、流程、设备、统计），缺失子项跳过。用流程图式文字表达，不堆在一页
- **主要结果**：每页聚焦一个核心结果，必须有具体数据支撑，用表格或结构化数据呈现
- **讨论与解读**：重点是**解释与对比**，不是复述结果。涵盖机制分析、意义、与已有文献对比
- **结论与局限性**：高度概括核心结论；局限性优先用作者自己承认的不足
- **未来展望**：优先提取原文 future work；若无明确说明可谨慎归纳并标注
- **致谢与参考文献**：基金来源（无则省略）+ 核心引用 5-8 篇

---

## §3 单页写作规范

- **标题**：体现该页唯一主题，禁止模糊标题（如"结果分析""总结"）。好的标题带结论倾向，如"高温处理显著提升催化活性"
- **正文**：要点形式，每条 ≤ 25 字，每页 3-6 条，字号 ≥ 18pt，禁止大段堆砌
- **数据**：优先表格或结构化列表（指标→数值→对比），不写描述性长段
- **语言**：全文中文，专业术语保留英文（如 p-value、ANOVA），表述正式
- **强调**：关键数值和核心结论**加粗**
- **方法表达**：流程图式文字（步骤编号、箭头关系），避免堆术语

---

## §4 逻辑约束

### 必须遵守的叙事顺序

```
背景 → 问题 → 目的/假设 → 方法 → 结果 → 解释 → 结论 → 局限 → 展望
```

### 必须避免的问题

| 问题 | 说明 |
|------|------|
| 背景泄露结果 | 背景页不得包含研究发现 |
| 结果无数据 | 每个结果页必须有数据支撑 |
| 讨论重复结果 | 讨论页重点是解释与对比，不是复述 |
| 结论复制前文 | 结论要高度概括，不是拼贴 |
| 局限与展望混写 | 必须分成独立章节 |
| 方法堆满一页 | 方法部分应拆分为 2-3 页 |
| 信息量失衡 | 不要有的页过满、有的页过空 |

---

## §5 缺失信息处理

| 缺失项 | 处理方式 |
|--------|----------|
| 无明确假设 | §2.4 只写研究目的，不写假设 |
| 无实验设备信息 | 方法部分不设"实验设备"子页 |
| 无基金来源 | 致谢页不写基金信息 |
| 无明确 future work | 基于局限性谨慎归纳，标注"基于论文内容归纳" |
| 影响因子 / JCR 分区不可查 | 标注"待补充"，不得虚构 |

---

## §6 视觉设计规范

整套 PPT 必须呈现**理性、克制、正式、可信、结论导向**的视觉效果，参考高校文献汇报、国自然项目答辩、职称申报答辩、科研技术汇报的共同设计语言。风格气质必须正式、学术、专业、稳重，强调结构化表达与研究逻辑。

适用场景：文献汇报、组会汇报、课题进展汇报、国家自然科学基金申请/结题答辩、职称申报答辩、科技奖/科研项目技术汇报。

### 整体风格

- 统一采用**白色背景**
- 全稿只使用**一种低饱和深色主色**，不得出现多个互不相关的强调色系统
- 页面必须体现"**标题引导 → 内容展开 → 结论提炼**"的阅读顺序
- 所有页面遵循严格对齐和统一网格，不允许元素漂浮、随意摆放

### 配色规范

**主色系统（全稿只选一个）：**

| 主色方案 | 色值 | 适用方向 |
|----------|------|----------|
| 深蓝（默认） | `1F3864` | 通用学术汇报 |
| 深红 | `8B0000` | 医学、生命科学 |
| 深绿 | `1B5E20` | 农学、环境、生态 |
| 深紫 | `4A148C` | 材料、化学、交叉学科 |

**色彩角色分配：**

| 角色 | 规则 |
|------|------|
| 主色 | 章节编号、标题引导条、导航栏、重点边框、结论框、页脚色带、核心图标 |
| 正文色 | 统一使用 `333333`（深灰）或 `000000`（黑色） |
| 辅助色 | 主色 15% 透明度的浅色版本，用于表格底纹、分隔线、卡片背景 |
| 强调色 | 主色加深或暗红 `8B0000`，**仅用于**关键结论、关键数据，少量使用 |

**配色禁令：**
- 禁止高饱和撞色、渐变炫光、彩虹配色、荧光色
- 禁止大面积渐变、光效、拟物质感
- 同一页不得出现多个互不相关的强调色
- 图表颜色必须与主色体系统一

### 字体与文字层级

全稿无衬线字体，中英文各限一种。

**字体配对：**

| 用途 | 中文 | 英文 |
|------|------|------|
| 全稿统一 | 微软雅黑 | Calibri |

**字号层级：**

| 元素 | 字号 | 样式 | 颜色 |
|------|------|------|------|
| 封面标题 | 40-48pt | 加粗 | 主色 |
| 一级标题（页面标题） | 32-40pt | 加粗 | 主色 |
| 二级标题（区块标题） | 22-24pt | 加粗 | 主色或深灰 |
| 正文要点 | 18-20pt | 常规 | 深灰 `333333` |
| 图注 / 页码 / 辅助说明 | 12-14pt | 常规 | 浅灰 `808080` |

**文字约束：**
- 不得混用多种字体
- 不得使用书法体、手写体、艺术字、装饰体
- 避免大段连续文字——文字必须压缩成可汇报语言
- 不要为了填满版面而压缩字号
- 专业术语保留英文原文，中英混排必须自然清晰
- 强调优先通过：加粗、独立结论框、局部变色、编号标签实现
- 避免过度使用斜体、下划线、彩色字

### 版式规则

采用"**顶部标题区 + 主内容区 + 页脚/页码区**"的稳定三段结构。

**间距规范：**
- 页面边距：≥ 0.5"
- 内容块间距：0.3-0.5"
- 标题区、正文区、图表区之间要有明确分隔

**版式原则：**
- 每页内容应**充分利用页面空间**，内容区域填充率不低于页面可用面积的 **70%**，避免大面积留白导致页面空旷
- 每页只承载**一个核心信息任务**，不要一页混杂多个主题
- 页面元素严格对齐，边距统一，视觉重心稳定
- 信息密度可以中等偏高，但必须**模块化、分区清楚、可快速扫描**
- 留白仅用于元素间分隔，不要出现大块无内容区域
- 图表、表格、图片较多时，优先拆页，不压缩堆叠
- 当内容较少时，应放大字号、扩展图表尺寸或增加结论框来充实页面，而非缩在角落
- 长篇汇报可使用"左侧固定导航栏 + 右侧内容区"

**各类页面版式指引：**

| 页面类型 | 推荐版式 |
|----------|----------|
| 封面 | 标题突出居中或居左；学校/单位/课题组整齐排列；作者与日期放底部或侧下方 |
| 目录 | 编号化列表，一级模块控制在 4-6 个以内 |
| 研究背景 | 左右分栏或要点列表 |
| 技术路线/研究思路 | 流程图、阶段块、箭头链路、步骤编号 |
| 研究结果 | 表格/数据 + 解释文字 + **独立结论框**（结构闭环） |
| 结论/创新/展望 | 减少图量，使用摘要框、对比框、编号要点、分组卡片 |

### 图表与表格规则

图表风格偏**科研论文式与正式汇报式**。

**图表要求：**
- 图表必须规整摆放，边界清晰，对齐统一
- 坐标轴、图例、标签清楚可辨
- 图表颜色与主色体系统一
- 不做商业化重绘，不加复杂阴影、立体效果、夸张渐变
- **禁止**：3D 图表、花哨图例、拟物质感

**表格要求：**
- 优先简洁排版，突出关键对比项和关键数字
- 重点数据可通过加粗、边框或浅色底纹适度强调

**PptxGenJS 图表学术风格参考：**

```javascript
slide.addChart(pres.charts.BAR, chartData, {
  x: 0.5, y: 1, w: 9, h: 4, barDir: "col",
  chartColors: ["1F3864", "B4C7E7", "D6DCE4"],        // 与主色体系统一
  chartArea: { fill: { color: "FFFFFF" } },             // 白色背景
  catAxisLabelColor: "404040",                           // 深灰轴标签
  valAxisLabelColor: "404040",
  valGridLine: { color: "E2E8F0", size: 0.5 },          // 细浅网格线
  catGridLine: { style: "none" },                        // 隐藏纵向网格
  showValue: true,
  dataLabelPosition: "outEnd",
  dataLabelColor: "1F3864",
  showLegend: false,
});
```

### 结论表达方式

关键结论必须**独立成框、成条或成摘要区**，不允许埋在正文段落中。

**结果页结构闭环：**
```
数据支撑 → 解释归纳 → 结论落点
```

**允许的强调方式：**
- 加粗
- 独立结论框（主色细边框 + 辅助色浅底纹）
- 局部变色（使用强调色，仅关键数值）
- 编号标签
- 独立成行

**约束：**
- 每页只突出 **1 个主结论**，最多 2-3 个辅助点
- 标题尽量带结论倾向，不要只写空泛栏目名
- 强调应少而准，不能整页到处加粗
- 强调方式在整套 PPT 中保持一致
- 强调的是研究发现、创新点、应用价值或汇报判断，不是视觉装饰

### 一致性要求

整套 PPT 必须保持统一的视觉系统：

- 统一的标题样式（字体、字号、颜色、位置）
- 统一的正文样式
- 统一的主色体系（全稿只有一个主色）
- 统一的图表风格
- 统一的页边距与对齐方式
- 统一的结论框样式
- 统一的页脚/页码样式

**不得出现**某一页极简、某一页复杂，或某一页偏学术、某一页偏宣传海报的风格跳跃。

### 禁止事项

**视觉禁令：**
- 不使用 accent lines（标题下装饰线）——AI 生成痕迹过强
- 不使用大面积渐变、光效、阴影、拟物质感
- 不使用低对比度文字（浅色文字 + 浅色背景）
- 不在文字区使用复杂背景

**风格禁令：**
- 不要商业宣传风、互联网运营海报风
- 不要高饱和跳色、彩虹配色
- 不要密集堆字
- 不要图表样式混乱（各页风格不统一）
- 不要让 logo、校徽、单位名抢过标题和结论
- 不要让页面看起来像招生简章、品牌发布会或产品宣传册

**最终效果标准：** 输出必须像真实高校、医院、实验室、科研院所会使用的正式答辩 PPT——第一眼看上去专业、整洁、可信，听众能快速抓住每页重点，所有设计都服务于学术内容表达

## §7 质量验证

生成后必须执行质量验证，不得跳过。第一次渲染几乎不可能完全正确——以找问题的心态检查，而非确认通过。

### 内容验证

```bash
python -m markitdown output.pptx
```

检查内容完整性、文字错误、章节顺序。

**占位符残留检查：**

```bash
python -m markitdown output.pptx | grep -iE "xxxx|lorem|ipsum|this.*(page|slide).*layout"
```

有结果则必须修复后才能交付。

**学术内容专项检查：**
- 封面标题是否与原文一致
- 结果页是否每页都有数据支撑
- 背景页是否泄露了结果
- 讨论页是否只是重复了结果
- 是否有虚构的数据或信息
- 所有章节是否遵循 §2 的固定顺序
- 配色、字号、强调方式是否全套一致

### 视觉验证（可选）

如果环境中有 LibreOffice 和 Poppler，可转图检查布局问题：

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
pdftoppm -jpeg -r 150 output.pdf slide
```

检查项：元素重叠、文字溢出、间距不均、低对比度文字、占位符残留、配色不统一。

### 验证循环

1. 生成幻灯片 → 内容验证
2. 发现问题则修复
3. 修复后重新验证受影响的部分

## §8 技术执行

### 路径选择

| 场景 | 技术路径 | 参考文档 |
|------|----------|----------|
| 有模板 .pptx 文件 | 解包 → 编辑 XML → 清理 → 重新打包 | [editing.md](editing.md) |
| 无模板，从零创建 | PptxGenJS (Node.js) | [pptxgenjs.md](pptxgenjs.md) |
| 仅提取/分析论文内容 | markitdown 直接读取 | — |

### 模板编辑流程概要

```bash
# 1. 分析模板
python scripts/thumbnail.py template.pptx
python -m markitdown template.pptx

# 2. 解包
python scripts/office/unpack.py template.pptx unpacked/

# 3. 结构操作（增/删/排序幻灯片，必须在编辑内容前完成）
python scripts/add_slide.py unpacked/ slide2.xml        # 复制幻灯片
python scripts/add_slide.py unpacked/ slideLayout2.xml   # 从布局创建

# 4. 编辑内容（使用 Edit 工具修改各 slide XML）

# 5. 清理 + 打包
python scripts/clean.py unpacked/
python scripts/office/pack.py unpacked/ output.pptx --original template.pptx
```

### 从零创建流程概要

```bash
# 编写 Node.js 脚本，使用 PptxGenJS 生成
node generate_slides.js
```

详见 [pptxgenjs.md](pptxgenjs.md) 中的 API 参考和图表代码。

### 依赖

- `pip install "markitdown[pptx]"` — 文本提取
- `pip install Pillow` — 缩略图网格
- `pip install defusedxml` — XML 安全解析
- `npm install -g pptxgenjs` — 从零创建
- LibreOffice (`soffice`) — PDF 转换（可选，用于视觉验证）
- Poppler (`pdftoppm`) — PDF 转图片（可选，用于视觉验证）
